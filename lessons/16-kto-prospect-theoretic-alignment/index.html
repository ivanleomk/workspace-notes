Introduction: Learning from Binary Feedback

In Lesson 04 (DPO) and Lesson 14 (SimPO), you learned how to align language models using preference pairs: given two outputs for the same input, the model learns to increase the probability of the preferred output and decrease that of the dispreferred one. This approach has proven highly effective, but it has a practical limitation: preference data is relatively scarce and expensive to collect.

The Binary Feedback Question

What if you only have binary labels—"this output is good" or "this output is bad"—instead of paired preferences?

Binary feedback is far more abundant, faster, and cheaper to collect than preferences. You can get it from thumbs-up/thumbs-down buttons, approval/disapproval signals, or even implicit signals like whether a user accepted a suggestion. But can you match preference-based methods with this simpler signal?

KTO (Kahneman-Tversky Optimization) by Ethayarajh, Xu, Muennighoff, Jurafsky, and Kiela (2024) answers: yes. By framing alignment through the lens of prospect theory (work for which Daniel Kahneman shared the 2002 Nobel memorial prize in economics)—KTO matches or exceeds DPO performance at scales from 1B to 30B parameters, despite learning from a weaker signal.

Why Prospect Theory?

Prospect theory (Kahneman & Tversky, 1979, 1992) explains why humans make decisions about uncertain outcomes that don't maximize expected value. For example, humans are loss-averse: losing $100 hurts more than gaining $100 feels good. They're also risk-averse in gains (prefer a sure $50 over a 50% chance of $100) but risk-seeking in losses (prefer a 50% chance of losing $100 over a sure loss of $50).

The paper shows that successful alignment objectives like DPO and PPO-Clip implicitly model these human biases, which helps explain why they outperform simple cross-entropy training. The authors call these objectives Human-Aware Losses (HALOs). KTO takes this insight further by directly using the Kahneman-Tversky value function to derive a loss that:

  • Maximizes the utility of generations (not just the log-likelihood of preferences)
  • Works with binary desirable/undesirable labels
  • Incorporates loss aversion and a reference point based on KL divergence
  • Handles extreme data imbalances (e.g., 1:10 desirable:undesirable ratio)

Prospect Theory: How Humans Perceive Value

The Classical Problem

Classical economics assumes humans maximize expected value. Given a gamble that returns $100 with 80% probability and $0 with 20% probability, a person might accept a sure $60 to avoid the gamble, even though their certainty equivalent ($60) is less than the expected value ($80). (Example from arXiv v1 §3.1; later versions misprint the 20% outcome as $60.)

Why? Kahneman & Tversky (1979) introduced prospect theory, and Tversky & Kahneman (1992) proposed the parametric value function below, estimating the median parameters from experiments with monetary gambles.

The Kahneman-Tversky Value Function

The value function maps an outcome \( z \), relative to a reference point \( z_0 \), to its perceived (subjective) value:

$$ v(z; \lambda, \alpha, z_0) = \begin{cases} (z - z_0)^\alpha & \text{if } z \geq z_0 \text{ (gains)} \\ -\lambda(z_0 - z)^\alpha & \text{if } z < z_0 \text{ (losses)} \end{cases} $$

Where:

  • \( z_0 \) = reference point, the baseline against which gains/losses are measured
  • \( \alpha = 0.88 \) (median) = curvature, controls risk aversion (diminishing sensitivity away from \( z_0 \))
  • \( \lambda = 2.25 \) (median) = loss aversion coefficient, reflects that losses hurt more than equivalent gains feel good

Key Properties

1. Reference Dependence

Value depends on changes relative to \( z_0 \), not absolute outcomes. Winning $100 from $0 feels different than winning $100 from $1000.

2. Loss Aversion (\(\lambda > 1\))

Losses are weighted more heavily than gains. Losing $50 hurts approximately 2.25× more than gaining $50 feels good.

3. Diminishing Sensitivity (\(\alpha < 1\))

Concave in gains (risk-averse: prefer sure $50 over 50% of $100) and convex in losses (risk-seeking: prefer 50% chance of $100 loss over sure $50 loss).

Prospect Theory in LLM Alignment

In the alignment context, outcomes are not monetary but rewards measured in nats—the decrease in conditional surprisal when going from the reference model \( \pi_{\text{ref}} \) to the aligned model \( \pi_\theta \). The implied reward is:

$$ r_\theta(x, y) = l(y) \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} $$

where \( l(y) \) is a normalizing factor (e.g., \( \beta \) in DPO). As alignment proceeds, \( r_\theta \) should grow increasingly positive for desirable outputs and increasingly negative for undesirable ones.

The reference point \( z_0 \) is the expected reward from the human's perspective. In KTO, this is the KL divergence \( \text{KL}(\pi_\theta(y'|x) \| \pi_{\text{ref}}(y'|x)) \), representing the typical reward change across all outputs for input \( x \).

Human-Aware Losses (HALOs)

Definition

A loss function \( f \) is a HALO if it can be written as:

$$ f(\pi_\theta, \pi_{\text{ref}}) = \mathbb{E}_{x,y \sim \mathcal{D}} \left[ a_{x,y} \, v_{x,y} \left( r_\theta(x, y) - \mathbb{E}_Q[r_\theta(x, Y')] \right) \right] + C_\mathcal{D} $$

Where:

  • \( r_\theta(x, y) = l(y) \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} \) = implied reward
  • \( Q(Y'|x) \) = reference-point distribution (what humans compare against)
  • \( v_{x,y} : \mathbb{R} \to \mathbb{R} \) = value function, non-decreasing everywhere
  • \( a_{x,y} \in \mathbb{R} \setminus \{0\} \) = coefficient (e.g., scaling by importance)
  • \( C_\mathcal{D} \) = data-specific constant (doesn't depend on \( \pi_\theta \) or \( \pi_{\text{ref}} \))

Intuition: HALOs evaluate the human value of the reward relative to a reference point, not just the raw reward itself. This reference-dependent structure mirrors how humans judge outcomes in prospect theory.

Why HALOs Matter: DPO and PPO are HALOs

The paper proves (Theorem 3.5) that DPO and PPO-Clip are HALOs. This helps explain why they outperform simple cross-entropy methods: they implicitly model human biases like loss aversion and reference dependence.

DPO as a HALO

DPO's loss can be rewritten with \( v(z) = \log \sigma(z) \), \( Q = \delta_{y_l} \) (reference point is the rejected output \( y_l \)), and \( a_{x,y} = -1 \). The value function \( \log \sigma(\cdot) \) is concave everywhere, reflecting risk aversion in both gains and losses.

PPO-Clip as a HALO

Treating one PPO-Clip update as offline (advantages A fixed, \(\pi_{\text{ref}} = \pi_{\text{old}}\)), the paper writes it as a HALO with \(a = -A\) and \(v(z) = \min(e^z, 1+\epsilon)\) when \(A > 0\), \(\max(e^z, 1-\epsilon)\) when \(A < 0\) (Appendix B). The value stops increasing once the probability ratio leaves the trust region in the direction the advantage favors.

Experimental Evidence: HALOs vs Non-HALOs

The paper compares HALOs (DPO, offline PPO) with non-HALOs (SLiC, CSFT) across Pythia-{1.4B, 2.8B, 6.9B, 12B} and Llama-{7B, 13B, 30B} models (Section 3.3, Figure 2). All models are aligned on the same data (Anthropic-HH, OpenAssistant, SHP) and judged by GPT-4 against SFT targets:

  • HALOs match or outperform non-HALOs at every scale, though differences are only statistically significant (p < 0.05) at 13B+ parameters after multiple-comparison correction.
  • Only HALO-aligned Llama-{13B, 30B} models achieve ≥50% winrate (matching or exceeding the SFT targets).
  • Offline PPO with dummy +1/-1 rewards (no learned reward model!) matches DPO up to 13B, suggesting that inductive bias in the loss function can compensate for weak reward signals. However, offline PPO lags at 30B and suffers from hyperparameter sensitivity.

This motivates KTO: can we design a principled HALO using prospect theory that works with binary feedback and matches DPO more reliably?

KTO Design: Directly Maximizing Utility

Core Insight

DPO maximizes the log-likelihood of preferences. KTO instead directly maximizes the utility of generations using a Kahneman-Tversky-inspired value function. It requires only a binary signal: whether output \( y \) is desirable or undesirable for input \( x \).

The KTO Loss Function

The default KTO loss is (Equation 8 from paper):

$$ \mathcal{L}_{\text{KTO}}(\pi_\theta, \pi_{\text{ref}}) = \mathbb{E}_{x,y \sim \mathcal{D}} \left[ \lambda_y - v(x, y) \right] $$

Where:

$$ r_\theta(x, y) = \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} $$
$$ z_0 = \text{KL}(\pi_\theta(y'|x) \| \pi_{\text{ref}}(y'|x)) $$
$$ v(x, y) = \begin{cases} \lambda_D \sigma(\beta(r_\theta(x, y) - z_0)) & \text{if } y \sim y_{\text{desirable}}|x \\ \lambda_U \sigma(\beta(z_0 - r_\theta(x, y))) & \text{if } y \sim y_{\text{undesirable}}|x \end{cases} $$

And \( \lambda_y = \lambda_D \) if \( y \) is desirable, \( \lambda_U \) if undesirable.

Key Components

Value Function: Logistic \(\sigma(\cdot)\)

The original Kahneman-Tversky function \((z - z_0)^\alpha\) causes numerical instability due to the exponent. KTO uses \(\sigma(\beta z)\), which is also concave in gains and convex in losses, but numerically stable. The hyperparameter \(\beta\) controls risk aversion (see next section).

Reference Point \(z_0\): KL Divergence

Unlike DPO (where the reference is one dispreferred output \(y_l\)), KTO assumes humans judge \(y|x\) relative to all possible outputs. The reference point is the KL divergence from \(\pi_{\text{ref}}\), representing the typical reward shift. It is held fixed during backpropagation for stability.

Loss Aversion: \(\lambda_D, \lambda_U\)

Separate coefficients for desirable (\(\lambda_D\)) and undesirable (\(\lambda_U\)) examples replace the single \(\lambda\) in the original Kahneman-Tversky function. Default: \(\lambda_D = \lambda_U = 1\). For imbalanced data, set them so that \(\frac{\lambda_D n_D}{\lambda_U n_U} \in [1, 1.5]\) (Equation 9).

How KTO Works

For desirable examples: If the model increases the reward \( r_\theta(x, y) \) naively (e.g., by just boosting all token probabilities), the KL penalty \( z_0 \) also rises, and no progress is made. This forces the model to learn what specifically makes the output desirable, so the reward can rise while the KL stays flat or even decreases.

For undesirable examples: The same logic applies in reverse: the model must learn what makes outputs bad, decreasing their reward without increasing KL. The non-negativity of KL allows faster saturation in the loss regime (undesirable examples can drive \( z_0 - r_\theta \) large more easily).

KL Estimate (Practical Implementation)

Estimating \( z_0 = \text{KL}(\pi_\theta \| \pi_{\text{ref}}) \) by sampling from \( \pi_\theta \) is slow. Instead, KTO uses a biased but fast estimate by shifting outputs in the same microbatch to create mismatched pairs \(\{(x_1, y_2), (x_2, y_3), \ldots, (x_m, y_1)\}\):

$$ \hat{z}_0 = \max\left( 0, \frac{1}{m} \sum_{i=1}^{m} \log \frac{\pi_\theta(y_j|x_i)}{\pi_{\text{ref}}(y_j|x_i)} \right) $$

where \( j = (i \mod m) + 1 \). Clamping to 0 reduces variance while introducing upward bias. If KTO is preceded by SFT on the same desirable data and the SFT model is used as \( \pi_{\text{ref}} \), then KL quickly approaches zero and \( \hat{z}_0 \) can be set to 0 (Section 4.1).

The Value Function and Hyperparameters

Risk Aversion: \(\beta\)

The hyperparameter \(\beta \in \mathbb{R}^+\) controls the curvature of the value function. The greater \(\beta\), the more quickly the value saturates:

  • High \(\beta\): More risk-averse in gains (saturates quickly for positive \(r_\theta - z_0\)) and more risk-seeking in losses (saturates quickly for negative \(r_\theta - z_0\)).
  • Low \(\beta\): Less saturation, allowing the model to learn from a wider range of reward values.

Default: \(\beta = 0.1\) works well in most cases (Section 4.2; arXiv v5). Table 1 lists the tuned per-setup values (0.05–0.50). Smaller values (\(\beta \in [0.01, 0.10)\)) are recommended when applying KTO to a model that has already been finetuned on the same data. Larger values (\(\beta \in (0.10, 0.50]\)) are recommended when the reference model is already very performant (e.g., Llama-3 8B Instruct: \(\beta = 0.25\)).

Loss Aversion: \(\lambda_D, \lambda_U\)

These control the degree of loss aversion—how much the model weighs undesirable examples relative to desirable ones:

  • \(\lambda_D\): Weight for desirable examples.
  • \(\lambda_U\): Weight for undesirable examples.
  • Default: \(\lambda_D = \lambda_U = 1\) (loss-neutral).

For imbalanced data (e.g., 10× more undesirable than desirable examples), the paper recommends setting \(\lambda_D, \lambda_U\) such that (Equation 9, Section 4.2):

$$ \frac{\lambda_D n_D}{\lambda_U n_U} \in \left[1, \frac{3}{2}\right] $$

where \(n_D\) and \(n_U\) are the counts of desirable and undesirable examples. For a 1:10 ratio, set \(\lambda_U = 1, \lambda_D \in [10, 15]\). This empirically-determined interval implies that after adjusting for class imbalances, gain sensitivity yields better performance than loss sensitivity—producing good outputs is more important than avoiding bad ones for success on most benchmarks.

Learning Rate

KTO is more sensitive to learning rate than to any other hyperparameter (Section 4.2). The optimal learning rate for KTO is typically 2× to 10× the optimal rate for DPO, because the reference-adjusted reward \(r_\theta - z_0\) is much smaller in magnitude than DPO's log-ratio reward.

Default: 5e-6 with AdamW works well for 8B models across all setups (with SFT, without SFT, when using an already instruction-tuned model, and with LoRA instead of full finetuning). The default DPO learning rate at the 8B scale is 5e-7. The paper's own experiments use the default DPO learning rate with RMSProp for all methods (for an apples-to-apples comparison), but recommend starting KTO at 5e-6 with AdamW. Smaller or larger models benefit from proportionally smaller or larger learning rates.

Learning Rate Diagnostic

If the learning rate is too aggressive, the implied rewards of both desirable and undesirable examples will decline. Ideally, only undesirable rewards should decline, with desirable rewards staying flat or increasing. If the reference model has already undergone SFT or alignment, the average reward of desirable examples may stay flat even under ideal settings, because the reference model is hard to improve upon.

Ablations: What Happens When You Change the Design?

The paper tests several variants of KTO on Zephyr-β-SFT aligned on UltraFeedback (Table 2, middle section):

Removing \(z_0\) (no reference point)

BBH: 52.6% → 49.0% (−3.6 pts)
GSM8K: 53.5% → 49.5% (−4.0 pts)

The reference point is crucial for KTO's performance.

Concave everywhere (like DPO)

Change \(v = 1 - \sigma(\cdot)\) to \(v = -\log \sigma(\cdot)\): BBH: 52.6% → 43.2% (−9.4 pts)
GSM8K: 53.5% → 42.5% (−11.0 pts)

Removing the symmetric S-shape (concave in gains, convex in losses) by making the value function concave everywhere, as in DPO, significantly hurts performance.

Risk-neutral (identity function)

Set \(v(z) = z\): BBH: 52.6% → 6.1% (total collapse!)

The saturation property of \(\sigma(\cdot)\) is essential.

These ablations confirm that KTO's design choices—the reference point, asymmetric value function, and saturation—are not arbitrary but critical to its success.

Results: KTO Matches or Exceeds DPO

Main Result: KTO ≥ DPO at All Scales

The paper evaluates KTO against DPO across Pythia-{1.4B, 2.8B, 6.9B, 12B} and Llama-{7B, 13B, 30B} models, all aligned on the same data (Anthropic-HH, OpenAssistant, SHP) and judged by GPT-4 against SFT targets (Figure 3, Section 4.3):

  • SFT+KTO is competitive with SFT+DPO at scales from 1B to 30B.
  • KTO alone is better than DPO alone for Llama-{7B, 13B, 30B}; the gap is significant (p < 0.01, Holm-corrected) at 7B and 30B.
  • Among Pythia models, there is no significant difference, suggesting a minimum model capacity is needed for these differences to emerge.

KTO Does Not Need SFT (at Sufficient Scale)

In the paper's experiments, KTO-aligned Llama-13B and 30B without SFT were competitive with SFT+KTO (Section 4.3). This is unique to KTO among the methods tested. The paper hypothesizes this is because KTO alone keeps the average response length roughly the same, while running DPO without SFT prior causes response length to increase dramatically (Figure 4).

When to Skip SFT

In the paper's experiments, KTO-aligned Llama-13B and 30B without SFT were competitive with SFT+KTO (Section 4.3). This saves a training stage. However, at Llama-7B, Figure 3 shows SFT+KTO ahead of KTO alone (approximate read).

Extreme Data Imbalance: Up to 90% Fewer Desirable Examples

The paper tests whether KTO secretly benefits from its 2n examples coming from n preference pairs (which might create hidden structure). They randomly discard increasingly large fractions of desirable data before aligning Llama-7B, handling imbalances by adjusting \(\lambda_D, \lambda_U\) per Equation 9 (Figure 5, Section 4.3):

  • With 90% of desirable data discarded (1:10 desirable:undesirable ratio, \(\lambda_U = 1, \lambda_D = 13.33\)), KTO still outperforms DPO (which uses the full balanced dataset).
  • The vast majority of undesirable examples no longer have a preferred counterpart, confirming that KTO does not rely on paired structure.

This demonstrates that KTO's success is not an artifact of the preference-pair structure—it genuinely learns from unpaired binary feedback.

One-y-per-x: KTO on Truly Unpaired Data

To further verify this, the paper aligns Mistral-7B on OpenAssistant using:

  • DPO on n pairs
  • Standard KTO on all 2n outputs
  • KTO (one-y-per-x): Only one y per x is used, removing any trace of paired preferences at the cost of reducing training data by 72%.

Results (Table 3):

Despite using 72% less data, KTO (one-y-per-x) still outperforms DPO (63.1% vs 60.0%) and even beats the official Mistral-7B-Instruct model (62.1%). This confirms that KTO works with truly unpaired binary feedback.

Human Evaluation: Larger KTO-DPO Gap

The paper also runs human evaluation on Mistral-7B models aligned on OpenAssistant (256 sampled prompts, 214 comparisons per method after skipping domain-expert questions; third-party annotation service; ± are 90% binomial CIs; Appendix D):

  • KTO winrate vs. SFT targets (humans): 72.9% ± 5.3%
  • DPO winrate vs. SFT targets (humans): 62.1% ± 5.7%
  • Gap: 10.8 percentage points (significant at p < 0.05)

In contrast, GPT-4-based evaluation shows a smaller gap (65.2% vs 60.0%, not significant). The larger gap in human evaluation suggests that KTO's utility-based objective better captures what humans actually prefer, even if GPT-4 judges don't fully reflect that.

Interpretation

The value function maps the reference-adjusted reward \( r_\theta - z_0 \) to its perceived human value. For desirable examples (blue), the value is \( \lambda_D \sigma(\beta(r_\theta - z_0)) \). For undesirable examples (red), the value is \( \lambda_U \sigma(\beta(z_0 - r_\theta)) \).

Notice the S-shaped curve for each type: it saturates quickly if \( \beta \) is high (risk-averse). Loss aversion is modeled by separate weights: \( \lambda_D \) applies only to desirable (gain) examples, and \( \lambda_U \) applies only to undesirable (loss) examples. Setting \( \lambda_U > \lambda_D \) makes losses hurt more than gains feel good. The reference point \( z_0 \) shifts the boundary between gains and losses.

Bridge to the Curriculum

How KTO Connects to Previous Lessons

Lesson 04: Direct Preference Optimization (DPO)

DPO requires paired preferences \( (x, y_w, y_l) \). KTO generalizes to binary feedback \( (x, y_{\text{desirable}}) \) or \( (x, y_{\text{undesirable}}) \), which is easier to collect. Breaking n preferences into 2n binary labels can yield better results with KTO. Both are HALOs, but KTO directly maximizes utility instead of preference log-likelihood.

Lesson 14: SimPO

SimPO eliminated DPO's reference model by using length-normalized average log-probability. KTO takes a different simplification: it keeps the reference model but removes the need for paired preferences. Both address DPO's practical limitations, but along orthogonal axes (memory efficiency vs data requirements).

Lesson 02: InstructGPT & RLHF

KTO, like DPO and SimPO, is an offline alternative to RLHF's PPO stage. The paper proves that PPO-Clip is a HALO, and KTO uses a similar but more principled prospect-theoretic value function. The paper's offline-PPO baseline (Section 3.3, dummy +1/−1 rewards) shows that even simple rewards can succeed with the right inductive bias.

Lesson 05: LLM-as-Judge & MT-Bench

KTO is evaluated using GPT-4 as a judge (winrate against SFT targets), the same approach as MT-Bench and AlpacaEval. Interestingly, human evaluation shows a larger KTO-DPO gap than GPT-4 evaluation, suggesting KTO's utility-based objective better captures human preferences than preference likelihood does.

Lesson 10: Tülu 3 - Open Post-Training

Tülu 3's pipeline (SFT → DPO → RLVR) could substitute KTO for DPO, potentially improving data efficiency (KTO handles extreme imbalances) and skipping SFT when the base model is strong enough. Tülu 3's preference stage uses paired data with DPO; KTO would be a candidate drop-in where only unpaired thumbs-up/down labels exist (our suggestion, not tested in either paper).

Lesson 13: TruthfulQA - Imitative Falsehoods

TruthfulQA showed that imitation learning from web text teaches models human misconceptions. KTO, like DPO, addresses this by learning from human feedback (binary or preference) that encodes truthfulness judgments. Binary feedback for truthfulness is easier to collect than preferences: "Is this answer truthful?" (yes/no) vs. "Which of these answers is more truthful?" (comparison).

The Bigger Picture: Data Efficiency and Practical Alignment

Progression of Alignment Methods

  1. Classical RLHF (Lesson 02): SFT → Reward Model → PPO. Requires preference data, reward model training, and online sampling. Complex and unstable.
  2. DPO (Lesson 04): SFT → DPO. Requires preference data. Simpler than RLHF, but preferences are expensive to collect.
  3. SimPO (Lesson 14): SFT → SimPO. Requires preference data but eliminates reference model for memory efficiency.
  4. KTO (Lesson 16): (Optional SFT) → KTO. Requires only binary feedback, which is abundant and cheap. Handles extreme imbalances. Can skip SFT for strong base models.

KTO represents a shift from preference-centric to utility-centric alignment, opening the door to using richer and more diverse forms of human feedback.

When to Use KTO vs DPO vs SimPO

Use KTO when:

  • You have binary feedback (thumbs-up/down, approval/disapproval)
  • Your data is highly imbalanced (e.g., 10× more negatives than positives)
  • Your preference data is noisy or intransitive (multiple annotators disagree)
  • You want to skip SFT (if base model is strong enough, e.g., 13B+)
  • You want to break n preferences into 2n examples for better data efficiency

Use DPO when:

  • You have clean, paired preference data
  • Your data has low noise and little intransitivity
  • You have existing DPO pipelines and infrastructure
  • You need a strictly paired (y_w, y_l) formulation, e.g., to reuse existing DPO tooling

Use SimPO when:

  • You have preference data but want to save memory (no reference model)
  • Length exploitation is a concern
  • You prioritize generation likelihood alignment
  • You want simpler implementation (no reference model management)
