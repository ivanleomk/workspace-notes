Why Evaluate Instruction Following?

Language models are increasingly used as instruction-following assistants— users give specific instructions and expect models to comply precisely. But how well do models actually follow instructions?

Traditional benchmarks test knowledge (MMLU), reasoning (GSM8K), or code generation (HumanEval). IFEval focuses specifically on instruction-following ability—can a model satisfy explicit constraints like "write in all caps", "use exactly 250 words", or "include keywords X, Y, Z"?

Key Innovation: Verifiable Constraints

IFEval uses objectively verifiable instructions that can be checked programmatically, without human judgment. This makes evaluation:

  • Objective: No ambiguity—either the constraint is satisfied or it isn't
  • Scalable: Automated checking instead of manual human evaluation
  • Reproducible: Same result every time, no inter-annotator disagreement
  • Training-friendly: Clear binary signal for reinforcement learning

What is IFEval?

IFEval (Instruction-Following Evaluation) is a benchmark introduced by Zhou et al. (2023) to measure how well language models follow explicit, verifiable instructions.

Key Facts

  • 541 prompts with 1-3 verifiable instructions each
  • ~1,100 total instructions across 25 distinct instruction types
  • 9 categories: change_case, combination, detectable_content, detectable_format, keywords, language, length_constraint, punctuation, startend
  • Two accuracy levels: Prompt-level (all instructions must pass) and instruction-level (per-instruction accuracy)
  • Two strictness levels: Strict (exact compliance) and loose (allows minor deviations)

Example Instructions

Example 1 (length_constraint):

"Write a 250-word essay about climate change."

Verification: Count words, check if exactly 250.

Example 2 (keywords + change_case):

"write a paragraph about space exploration that includes the words 'galaxy', 'telescope', and 'discovery'. your entire response should be in lowercase."

Verification: Check all three keywords present AND all letters are lowercase.

Example 3 (startend + punctuation):

"Write about technology. Start with 'In the modern world' and end with 'transforming society'. Do not use any commas."

Verification: Check first/last phrases match exactly AND no commas in the response.

Verifiable vs Subjective Evaluation

Verifiable (IFEval)

  • Objective: Programmatically checkable
  • Binary: Pass or fail, no ambiguity
  • Scalable: Automated checking
  • Examples:
    • Word count is exactly 250
    • Response contains keyword "robot"
    • All text is lowercase
    • No commas present

Subjective (MT-Bench, AlpacaEval)

  • Subjective: Requires human/LLM judgment
  • Graded: Quality scales, inter-rater variance
  • Manual: Human evaluation or LLM-as-judge
  • Examples:
    • Is the response helpful?
    • Does it sound natural?
    • Is the explanation clear?
    • Is the tone appropriate?

Why Both Matter

Verifiable evaluation (IFEval) tests precise control and constraint satisfaction— critical for tool use, API calls, and structured output generation.

Subjective evaluation (MT-Bench, AlpacaEval) tests helpfulness, creativity, and user satisfaction—critical for conversational AI and assistant quality.

Modern post-training pipelines (Lesson 10: Tülu 3) optimize both: use verifiable rewards for RLVR on IFEval/GSM8K/MATH, and use preference learning (DPO) for subjective quality.

Strict vs Loose Accuracy

IFEval defines two levels of strictness when checking instruction compliance:

Strict vs Loose Verification

Strict

Exact compliance required

  • Word count: Exactly 250 words (not 249 or 251)
  • Keywords: Must appear the exact number of times specified
  • Format: Must match the pattern precisely

Loose

Minor deviations allowed

  • Word count: 249-251 acceptable for "250 words"
  • Keywords: Meeting minimum threshold counts as success
  • Format: Small formatting variations accepted

Prompt-Level vs Instruction-Level

IFEval reports accuracy at two granularities:

  • Prompt-level: ALL instructions in a prompt must pass (if any instruction fails, the entire prompt fails)
  • Instruction-level: Each instruction is scored independently

Key Insights from Table 3

  • GPT-4 strict-loose gap: ~2.2 points (prompt-level). Small gap suggests GPT-4 either gets it exactly right or misses entirely—few "near misses".
  • PaLM 2 S strict-loose gap: ~3.9 points (prompt-level). Larger gap indicates more attempts that are close but not exact.
  • Instruction-level higher than prompt-level: GPT-4's instruction-level strict (83.57%) exceeds prompt-level strict (76.89%) because a single failed instruction fails the entire prompt.

Key Findings

1. Combination Instructions Are Hardest

Both models struggle most with combination instructions (satisfying multiple constraints simultaneously). GPT-4 achieves only ~73%, and PaLM 2 S drops to ~37%. This reveals a fundamental challenge: models can often handle individual constraints but fail when required to satisfy them all together.

2. Language Instructions Are Easiest

Both models achieve ~96% on language instructions (responding in French, Spanish, etc.). This is the only category where they tie, indicating multilingual capabilities are well-developed in modern LLMs.

3. Precise Control Varies Widely by Category

GPT-4 excels at startend (~93%) and detectable_content (~96%), but struggles with punctuation (~66%). PaLM 2 S shows even more variation: strong on language (~96%) and decent on detectable_content (~73%), but very weak on combination (~37%) and startend (~45%).

4. Largest Performance Gap: startend

The startend category shows a 48-point gap (GPT-4 ~93% vs PaLM 2 S ~45%)—the largest difference across all categories. This suggests GPT-4 has much better control over response boundaries, likely due to superior instruction-tuning or architectural advantages.

Why IFEval Matters for Post-Training

IFEval's verifiable nature makes it ideal for Reinforcement Learning from Verifiable Rewards (RLVR, introduced in Lesson 10: Tülu 3):

  • No reward model needed: Instruction compliance can be checked programmatically
  • Binary signal: Clear pass/fail for each constraint
  • Training-friendly: Immediate feedback for RL optimization
  • Complements subjective tasks: Use RLVR for IFEval/GSM8K/MATH (verifiable) and DPO for chat quality (subjective)

Connection to Post-Training

IFEval has become a critical benchmark in modern post-training pipelines because it provides verifiable rewards that enable more reliable reinforcement learning.

RLVR: Reinforcement Learning from Verifiable Rewards

In Lesson 10 (Tülu 3), we saw how RLVR extends reinforcement learning to tasks with objective ground truth. IFEval is perfect for this:

  • No learned reward model: Unlike RLHF (Lesson 02), which needs a trained reward model, IFEval instructions can be checked programmatically
  • Binary feedback: Each instruction either passes or fails—no ambiguity
  • Scalable training: Generate many responses, check compliance automatically, and use passing examples as positive signals for RL

Multi-Objective Optimization

Modern post-training combines:

  • Verifiable tasks (RLVR): IFEval, GSM8K, MATH, HumanEval—objective correctness
  • Subjective tasks (DPO): Chat quality, helpfulness, safety—preference learning

This dual approach ensures models are both precisely controllable (IFEval) and naturally helpful (preference data).

Tülu 3 Results on IFEval

Tülu 3 70B applies RLVR to IFEval, improving instruction-following accuracy:

  • SFT baseline: 82.1%
  • + DPO: 82.6% (+0.5 points)
  • + RLVR: 83.2% (+0.6 points from DPO, +1.1 total)

The gains are modest but consistent, showing that verifiable rewards help even when base instruction-following is already strong.

Key Takeaways

  1. IFEval measures verifiable instruction-following across 9 categories with objective, programmatic checking
  2. Combination instructions are hardest for both GPT-4 (~73%) and PaLM 2 S (~37%)— satisfying multiple constraints simultaneously is difficult
  3. Language instructions are easiest, with both models achieving ~96% accuracy
  4. GPT-4 excels at precise control, especially on startend (~93% vs ~45% for PaLM 2 S)
  5. Verifiable constraints enable RLVR, allowing post-training with objective rewards instead of learned reward models
