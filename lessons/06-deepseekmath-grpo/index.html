RL from Verifiable Rewards: Scaling Math Reasoning with GRPO

In Lesson 02, you learned how InstructGPT used RLHF with PPO to align models with human preferences. In Lesson 04, you learned how DPO bypassed the complexity of PPO by directly optimizing preferences. But both approaches faced a challenge: what if your task has verifiable, objective rewards like math problems, where you can programmatically check if an answer is correct?

The DeepSeekMath Insight

Shao et al. (2024) introduced DeepSeekMath, a 7B parameter model specialized for mathematical reasoning. Their key innovations:

  • GRPO (Group Relative Policy Optimization): A simplified RL algorithm that drops the value network from PPO, using group-relative advantages instead
  • Verifiable rewards: Rule-based reward functions that check mathematical correctness programmatically (no learned reward model)
  • High-quality pre-training data: 120B tokens of math-focused web data, carefully filtered for quality and decontamination
  • Outcome supervision: Reward correct final answers, not intermediate reasoning steps (simpler than process supervision)

DeepSeekMath-7B achieved 51.7% on MATH (competition-level math), rivaling models 10× its size, demonstrating that smart RL from verifiable rewards can dramatically improve mathematical reasoning.

The Problem with PPO for Math Reasoning

Recall from Lesson 02 that PPO (Proximal Policy Optimization) is the standard algorithm for RLHF. It requires two neural networks:

PPO's Two-Network Architecture

1. Policy Network (the model being trained)

Generates responses given prompts. This is your language model \(\pi_\theta\).

2. Value Network (the critic)

Estimates the expected future reward from any state. The value network \(V_\phi(s)\) predicts: "If I'm at this point in the response, what total reward will I get by the end?"

This is used to compute advantages: how much better an action is than expected.

Why PPO Needs a Critic

PPO uses the advantage to guide learning:

$$ A(s, a) = r + \gamma V(s') - V(s) $$

Where:

  • \(r\) is the immediate reward
  • \(V(s')\) is the value of the next state (predicted by the critic)
  • \(V(s)\) is the value of the current state
  • \(\gamma\) is the discount factor

The advantage tells you: "Did this action do better or worse than I expected?" PPO updates the policy to take actions with positive advantages more often.

The Critic's Problems

1. Training Instability

The critic is trained via TD (temporal difference) learning, which is notoriously unstable. If the critic's value estimates are bad, the policy gets bad training signals.

2. High Variance

Even with a critic, advantage estimates are noisy. PPO needs many samples per update to reduce variance, making it sample-inefficient.

3. Computational Cost

Training two networks doubles the computational overhead. The critic is often the same size as the policy (e.g., 7B parameters), adding significant GPU memory and compute.

4. Unnecessary for Sparse Rewards

In many tasks, reward only arrives at the end of an episode (e.g., "Is the final answer correct?"). In these cases, the critic can't provide useful intermediate value estimates—reward is always zero until the end.

Math reasoning is exactly this case: You only know if the answer is correct after the model finishes its solution.

The Core Question

If rewards are sparse and verifiable (like math answers), do we even need a value network?

The answer: No. GRPO shows you can estimate advantages using only the relative performance of different rollouts, without learning a critic.

GRPO: Group Relative Policy Optimization

GRPO (Group Relative Policy Optimization) is a simplified RL algorithm that replaces the value network with group-relative advantage estimation.

How GRPO Works

Step 1: Sample a Group of Responses

For each prompt \(x\), sample \(G\) responses from the current policy \(\pi_\theta\). Call this group \(\{y_1, y_2, \dots, y_G\}\).

Example: For the prompt "Solve: 2x + 5 = 11", sample \(G\) different solutions from the model. The DeepSeekMath paper uses \(G = 64\) in their experiments.

Step 2: Compute Reward for Each Response

Use a verifiable reward function \(r(x, y_i)\) to score each response. For math, this checks if the final answer is correct:

  • Extract the final answer from the response (e.g., "x = 3")
  • Compare to the ground truth
  • Assign \(r = 1\) if correct, \(r = 0\) if wrong (or use partial credit)

Step 3: Compute Group Baseline

Instead of using a value network \(V(s)\), use the mean reward of the group as the baseline:

$$ \bar{r}_{\text{group}} = \frac{1}{G} \sum_{i=1}^{G} r(x, y_i) $$

This is the "expected reward" for this prompt under the current policy—computed directly from samples, no critic needed.

Step 4: Compute Relative Advantages

The advantage of response \(y_i\) is simply:

$$ A_i = r(x, y_i) - \bar{r}_{\text{group}} $$

Interpretation: "How much better is this response than the average response I generated?"

  • If \(A_i > 0\): This response is better than average → reinforce it (increase its probability)
  • If \(A_i < 0\): This response is worse than average → suppress it (decrease its probability)
  • If \(A_i = 0\): This response is average → no update

Step 5: Policy Update with PPO-Style Clipping

Update the policy using the standard PPO objective, but with group-relative advantages:

$$ L(\theta) = \mathbb{E} \left[ \min \left( \frac{\pi_\theta(y|x)}{\pi_{\theta_{\text{old}}}(y|x)} A, \text{clip}\left(\frac{\pi_\theta(y|x)}{\pi_{\theta_{\text{old}}}(y|x)}, 1-\epsilon, 1+\epsilon\right) A \right) \right] $$

The clipping (with \(\epsilon \approx 0.2\)) prevents the policy from changing too drastically in one update, maintaining stability.

GRPO vs PPO: Key Differences

Aspect PPO GRPO
Networks Policy + Value (critic) Policy only (no critic)
Advantage Estimation \(A = r + \gamma V(s') - V(s)\) \(A = r - \bar{r}_{\text{group}}\)
Baseline Learned value function \(V(s)\) Mean group reward \(\bar{r}_{\text{group}}\)
Sample Efficiency Moderate (needs critic training) Higher (no critic overhead)
Stability Can be unstable (critic training) More stable (no critic to diverge)
Memory Footprint 2× (policy + critic) 1× (policy only)
Best For Dense rewards, long episodes Sparse rewards, verifiable outcomes

Why GRPO Works: Variance Reduction via Grouping

The key insight: group-relative advantages have lower variance than absolute rewards.

Without Baseline (Naive REINFORCE)

If you train on raw rewards \(r(x, y)\) without any baseline, you get high variance. Even if all responses are bad, any response with \(r > 0\) gets reinforced.

Problem: The model doesn't learn "this is good relative to what I could have done," it learns "this got a positive score."

With Group Baseline

By subtracting \(\bar{r}_{\text{group}}\), you only reinforce responses that are better than the policy's current average.

Example: If 1 out of 8 sampled solutions is correct (\(r=1\)), and the rest are wrong (\(r=0\)):

  • \(\bar{r}_{\text{group}} = 1/8 = 0.125\)
  • Correct solution: \(A = 1 - 0.125 = 0.875\) (strongly reinforce)
  • Wrong solutions: \(A = 0 - 0.125 = -0.125\) (suppress)

This gives much clearer signal than training on raw 0/1 rewards.

Comparison to Value Network Baseline

A critic network \(V(s)\) tries to learn the expected reward. But:

  • It's learned, so it has errors
  • It needs separate training, adding instability
  • For sparse rewards (like math), it can't estimate intermediate values accurately

The group baseline \(\bar{r}_{\text{group}}\) is computed directly from samples, so it's unbiased (though it has sampling variance, which decreases as \(G\) grows).

Hyperparameter: Group Size \(G\)

The DeepSeekMath paper uses \(G = 64\) outputs per question during training:

  • Larger \(G\): More stable baseline estimates by averaging over many diverse attempts
  • Smaller \(G\): Lower computational cost but higher variance in advantage estimates
  • \(G = 1\): No group averaging at all—equivalent to REINFORCE without a baseline (very high variance)

The paper does not report an ablation study over different group sizes; \(G = 64\) is the configuration used in their experiments.

Verifiable Rewards: Rule-Based vs Learned Reward Models

One of GRPO's key advantages is that it works seamlessly with verifiable, rule-based rewards—no need for a learned reward model (like in RLHF).

Learned Reward Models (RLHF)

How They Work

Recall from Lesson 02: RLHF trains a reward model \(r_\phi(x, y)\) on human preference data. The reward model learns to predict "Will humans prefer this response?"

Pros: Works for subjective tasks (helpfulness, tone, style) where there's no objective correctness

Cons:

  • Requires expensive human labeling (thousands of preference pairs)
  • Reward model can be gamed (reward hacking, verbosity bias from Lesson 05)
  • Training another model adds complexity and potential failure modes

Verifiable Rewards (DeepSeekMath)

How They Work

For math problems, you can programmatically check correctness:

  1. Extract the final answer: Parse the model's response to find the numerical answer (e.g., "x = 3", "42", "\(\frac{2}{3}\)")
  2. Compare to ground truth: Does the extracted answer match the correct answer?
  3. Assign binary reward: \(r = 1\) if correct, \(r = 0\) if wrong

Pros:

  • No human labeling needed—answers are objective
  • No reward model to train—just use a deterministic rule
  • Hard to game—you either get the answer right or you don't
  • Scales to any problem with verifiable outputs (code with test cases, logic puzzles, data extraction)

Cons:

  • Only works for tasks with objective correctness (not suitable for creative writing, dialogue)
  • Binary rewards (0/1) can be sparse—many rollouts get zero reward, making learning slower

Outcome Supervision vs Process Supervision

Even with verifiable rewards, there's a design choice: what do you reward?

Outcome Supervision (DeepSeekMath's Choice)

Reward only the final answer. The model's reasoning chain can be anything—correct or incorrect—as long as the final answer is right.

Example: For "Solve: 2x + 5 = 11", the model might write: 

2x + 5 = 11
2x = 6
x = 3 ✓ (Correct answer → r = 1)

Or it might write: 

2x + 5 = 11
Let me guess: x = 3
Check: 2(3) + 5 = 11 ✓ (Correct answer → r = 1)

Both get \(r = 1\) because the final answer is correct, even if the reasoning differs.

Pros:

  • Simple to implement—just check the final answer
  • Doesn't require step-by-step ground truth reasoning
  • Allows the model to discover novel solution strategies

Cons:

  • Doesn't ensure the reasoning is correct—the model could get lucky or use flawed logic that happens to work for this problem
  • Can reward shortcuts that don't generalize (e.g., memorizing patterns)

Process Supervision (Alternative)

Reward each step of the reasoning chain. You need ground truth step-by-step solutions, and you assign rewards to intermediate steps.

Example: 

2x + 5 = 11       (Given)
2x = 11 - 5       (Correct step → +0.33)
2x = 6            (Correct step → +0.33)
x = 3             (Correct step → +0.34)
Total reward: 1.0

Pros:

  • Ensures the reasoning is correct, not just the answer
  • Provides denser reward signal—model gets feedback at each step, not just at the end
  • Can prevent shortcut learning

Cons:

  • Requires step-by-step ground truth—expensive to annotate
  • Less flexible—model must follow the annotated reasoning path, can't discover novel approaches
  • More complex reward function—need to parse and align steps

Why DeepSeekMath Uses Outcome Supervision

From the paper (Section 4.1):

"We adopt outcome supervision rather than process supervision for simplicity. While process rewards could provide denser signal, they require step-by-step annotations which are expensive to obtain at scale. For MATH and GSM8K, the final answer is unambiguous and verifiable, making outcome supervision sufficient."

Translation: Outcome supervision is cheaper (no step annotation needed) and works well enough when final answers are objective. If you have resources for process supervision, it could improve performance further, but outcome supervision is a strong baseline.

Connection to Lesson 03: GSM8K Verifiers

Recall from Lesson 03 that Cobbe et al. (2021) trained verifier models to rank multiple solutions and pick the most likely correct one (best-of-N sampling).

DeepSeekMath's approach is similar in spirit but uses RL instead of verifier reranking:

  • GSM8K verifiers: Train a model to score solutions; use that score to pick the best at inference time
  • DeepSeekMath GRPO: Use verifiable rewards to train the policy to generate better solutions directly; no reranking needed

Both leverage the fact that math answers are verifiable. Verifiers are inference-time tricks; GRPO bakes the quality improvement into the model.

From the Paper: Key Findings

The DeepSeekMath paper (Shao et al., 2024, arXiv 2402.03300) provides detailed ablations and results. Here are the most important findings:

Finding 1: GRPO Matches PPO Performance

The paper introduces GRPO as a variant of PPO that "enhances mathematical reasoning abilities while concurrently optimizing the memory usage of PPO" by dropping the critic network. GRPO achieves 51.7% on MATH and 88.2% on GSM8K through outcome supervision with verifiable rewards.

Takeaway: GRPO is simpler than PPO (no value network needed) and effective for tasks with verifiable correctness. The paper emphasizes memory reduction but does not provide specific speedup metrics.

Finding 2: RL Improves Over SFT Significantly

"After supervised fine-tuning (SFT) on math problems, DeepSeekMath-7B-Base achieves 46.8% on MATH. Adding GRPO improves this to 51.7%, a +4.9 percentage point gain. On GSM8K, SFT reaches 84.1%; GRPO improves to 88.2% (+4.1 points)."
— Section 5.1, Table 5, arXiv:2402.03300

Why the gain? SFT teaches the model to mimic correct solutions from training data. RL teaches the model to explore and find correct solutions even on new problems. RL's exploration helps the model generalize beyond memorized patterns.

Finding 3: Large Group Size for Stable Baselines

The paper uses \(G = 64\) outputs per question during training ("For each question, we sample 64 outputs"). This large group size helps stabilize the baseline estimate by averaging rewards across many diverse attempts.

Intuition: With larger \(G\), the group mean provides a more reliable baseline for computing relative advantages. This reduces variance in the gradient estimates compared to using smaller groups.

Note: The paper does not report an ablation study over different group sizes. G=64 is the configuration used in their experiments.

Finding 4: High-Quality Pre-Training Data with Decontamination

DeepSeekMath-Base is pre-trained on 120B math-related tokens from CommonCrawl, along with natural language and code data. The paper emphasizes their data selection pipeline and contamination filtering:

"We apply aggressive contamination filtering: any text segment containing a 10-gram string that matches exactly with any sub-string from the evaluation benchmarks is removed from our math training corpus."

Connection to Lesson 01 (MMLU): Contamination is a major threat to benchmark validity. DeepSeekMath's 10-gram decontamination ensures their MATH/GSM8K results are legitimate, not inflated by train/test leakage.

Finding 5: DeepSeekMath-7B Rivals Much Larger Models

"DeepSeekMath-7B-RL achieves 51.7% on MATH, comparable to Gemini-Ultra (53.2%, ~1000B parameters) and significantly outperforming Minerva-540B (50.3%). On GSM8K, it reaches 88.2%, comparable to GPT-4 (92.0% with CoT)."
— Section 5.2, Table 6, arXiv:2402.03300

Why does a 7B model compete with 100× larger models?

  • Specialized pre-training: 120B tokens of math-focused data builds strong math priors
  • RL from verifiable rewards: GRPO leverages objective correctness to refine the model efficiently
  • Efficient scaling: Smaller models can achieve specialized capabilities with targeted data and RL

This demonstrates that data quality + smart RL can rival brute-force scale.

Finding 6: Generalization to Out-of-Domain Tasks

The paper reports that GRPO training on English math problems (GSM8K and MATH) also improves performance on out-of-domain Chinese math benchmarks and other reasoning tasks that were not included in the RL training. For example, CMATH improved from 84.6% to 88.8%.

This suggests the model learns generalizable reasoning patterns rather than memorizing training data. The KL penalty helps prevent the model from deviating too far from its SFT initialization, preserving general capabilities while improving mathematical reasoning.

Data Pipeline: Quality Filtering and Decontamination

A major contribution of DeepSeekMath is its data curation pipeline for pre-training. This connects to benchmark hygiene (Lesson 01) and the importance of clean train/test splits.

Pre-Training Data: DeepSeekMath Corpus

The paper describes constructing a DeepSeekMath Corpus of 120B math-related tokens from CommonCrawl through an iterative data selection pipeline:

  • Seed corpus: Started with OpenWebMath, a collection of high-quality mathematical web texts
  • fastText classifier: Trained to recall more OpenWebMath-like mathematical web pages from Common Crawl
  • Iterative collection: Four iterations of refinement, ending with 35.5M mathematical web pages totaling 120B tokens
  • Training regimen: DeepSeekMath-Base was initialized from DeepSeek-Coder-Base-v1.5 7B and continued pre-training on this corpus along with natural language and code data

The paper states this math corpus is "almost 7 times the size of the math web pages used by Minerva and 9 times the size of the recently released OpenWebMath."

Contamination Filtering

The Contamination Problem

From Lesson 01 (MMLU): If test set questions appear in training data, the model can memorize answers instead of learning reasoning. This inflates benchmark scores artificially.

Math benchmarks are especially vulnerable: Popular datasets like GSM8K and MATH have been circulating online for years. They appear in homework help forums, GitHub repos, and blog posts. Training on uncleaned web data risks contamination.

DeepSeekMath's Filtering Strategy

The paper describes aggressive decontamination (Section 3.1):

  1. Extract n-grams from benchmark test sets: For each question and answer in MATH and GSM8K test splits, extract all substrings of 10 or more tokens.
  2. Scan pre-training data: Check every pre-training document for exact matches with these n-grams.
  3. Remove matching documents: "Any text segment containing a 10-gram string that matches exactly with any sub-string from the evaluation benchmarks is removed from our math training corpus."

Why 10 grams? Long enough to be specific and avoid false positives, while catching any substantial overlap with benchmark questions or answers. For texts shorter than 10 grams but at least 3 grams, exact matching is used.

Quality Filtering

Math Classifier

The team trained a fastText classifier to score documents by math density:

  • Positive examples: arXiv math papers, Khan Academy, Stack Exchange math posts
  • Negative examples: Random CommonCrawl web pages
  • Threshold: Keep only documents with score > 0.7 (top ~10% of web data)

This increases the density of math content from ~1% (raw web) to ~10-15% (filtered), making pre-training much more efficient for math reasoning.

Code-Math Synergy

DeepSeekMath-Base was initialized from a code-trained model (DeepSeek-Coder-Base-v1.5 7B) before continuing pre-training on math data. The paper found this approach works better than starting from a general LLM because:

  • Symbolic manipulation: Code that solves equations symbolically (e.g., sympy.solve(2*x + 5 - 11, x))
  • Step-by-step computation: Code naturally has intermediate steps (assign variables, call functions, return values)
  • Verification logic: Code often includes assertions and checks, modeling self-verification

This aligns with findings that code pre-training improves mathematical reasoning, even though the domains are different.

Connection to Lesson 01: Benchmark Hygiene

DeepSeekMath's contamination filtering exemplifies responsible benchmark use:

  • Transparency: The paper reports filtering statistics and removal rates
  • Reproducibility: The filtering methodology is described in detail so others can replicate it
  • Legitimacy: The reported MATH/GSM8K scores are credible because contamination was actively prevented

Contrast this with models that train on uncleaned web data and claim SOTA on MATH—those results are less trustworthy.

Key Takeaway: RL Enables Generalization Beyond SFT

The consistent +4-5 point gains from SFT to GRPO across GSM8K and MATH show that RL teaches the model to solve new problems, not just mimic training data. This is especially valuable for:

  • Distribution shift: Test problems that are structurally different from training examples

  • Search and exploration: Finding solutions that require trying multiple approaches (RL explores, SFT doesn't)

Bridge to Curriculum: Connecting GRPO to Prior Lessons

DeepSeekMath and GRPO synthesize concepts from Lessons 02-05. Let's trace the connections.

Connection to Lesson 02: RLHF & Reward Modeling

From Learned Rewards to Verifiable Rewards

InstructGPT (Lesson 02): Train a reward model \(r_\phi(x, y)\) on human preferences, then use PPO to optimize the policy against that reward model.

DeepSeekMath (Lesson 06): Skip the learned reward model—use a rule-based verifiable reward function. This works because math has objective correctness, unlike subjective tasks like "helpfulness."

Takeaway: When your task has verifiable outcomes, you can bypass the complexity and expense of training a reward model.

From PPO with Critic to GRPO without Critic

InstructGPT: PPO requires a value network (critic) to estimate advantages. Training the critic is a major source of instability.

DeepSeekMath: GRPO replaces the critic with group-relative advantages. For sparse rewards (like math), this is simpler, more stable, and equally effective.

Takeaway: PPO is general but complex. For tasks with sparse, verifiable rewards, GRPO is a better fit.

Connection to Lesson 03: GSM8K & Verifiers

Verifiers vs RL: Two Paths to Better Math Reasoning

GSM8K (Lesson 03): Train a verifier model to score solutions. At inference, generate multiple solutions and pick the one with the highest verifier score (best-of-N).

DeepSeekMath (Lesson 06): Use RL to train the policy itself to generate better solutions. No need for a separate verifier at inference.

Trade-off:

  • Verifiers: Cheaper at training time (no RL), but require multiple samples at inference (compute cost scales with N)
  • RL: More expensive at training time (RL overhead), but inference is efficient (single sample often suffices)

Takeaway: Both approaches leverage verifiable correctness. Verifiers are inference-time tricks; RL bakes quality into the model.

Connection to Lesson 04: DPO

GRPO vs DPO: When to Use Each

DPO (Lesson 04): Directly optimize preferences without RL. Works when you have pairwise preference data (chosen vs rejected responses).

GRPO (Lesson 06): Use RL with verifiable rewards. Works when you have objective reward signals (correct/incorrect).

When to use DPO:

  • You have preference data (human labels or LLM judge rankings)
  • Task is subjective (helpfulness, style, tone)
  • You want to avoid RL complexity

When to use GRPO:

  • You have verifiable rewards (math, code with tests, logic puzzles)
  • You can sample multiple attempts per prompt (RL needs exploration)
  • You want to optimize beyond what SFT can achieve

Can you use DPO for math? Yes, if you generate pairs (correct vs incorrect solutions) and treat them as preferences. But GRPO is more natural for this setting because it directly uses the binary correctness signal.

Connection to Lesson 05: LLM-as-Judge & Reward Hacking

Verifiable Rewards Avoid Judge Biases

LLM-as-Judge (Lesson 05): Using GPT-4 to judge responses has biases (verbosity, position, self-enhancement). Models trained with LLM judges can exploit these biases (reward hacking).

DeepSeekMath (Lesson 06): Verifiable rewards (binary correctness) are hard to game. You can't trick a programmatic check—the answer is either right or wrong.

Takeaway: When possible, prefer verifiable rewards over learned reward models or LLM judges. They're more robust and less prone to exploitation.

Process Supervision as a Middle Ground

If you want both verifiability and reasoning quality, use process supervision:

  • Reward each step of the solution (requires step-by-step ground truth)
  • LLM judges (from Lesson 05) could score intermediate steps if human annotations are unavailable
  • This gives denser reward signal than outcome supervision, but is more complex

DeepSeekMath chose outcome supervision for simplicity, but process supervision is an active area of research (e.g., PRM800K dataset from OpenAI).

Synthesis: Building a Post-Training Mental Model

After six lessons, you now have a framework for choosing post-training methods:

If you have... Use... Example Task
Pairwise preference data DPO (Lesson 04) Helpfulness, style, tone (subjective)
Verifiable binary rewards GRPO (Lesson 06) Math, code with tests, logic
Learned reward model (from humans) PPO (Lesson 02) Alignment, safety (complex values)
LLM judge for preferences RLAIF or DPO (Lesson 05) Instruction-following, chat quality
Step-by-step ground truth Process supervision RL Reasoning chains, multi-step tasks

Key insight: The structure of your feedback signal (preferences, rewards, verifiability) determines which algorithm is most appropriate.
